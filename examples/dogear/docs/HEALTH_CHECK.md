## 1. AI 交付检查

| 检查项 | 状态 | 备注 |
|--------|------|------|
| 单文件不超300行 | 待检 | 所有 `.ts` / `.tsx` / `.css` 文件 |
| 无硬编码 URL | 待检 | API Base URL 应走环境变量 |
| 无 `any` 类型 | 待检 | 禁止 `any`，使用具体类型 |
| 函数参数和返回值有类型定义 | 待检 | 项目核心规范 |
| 组件先查 COMPONENTS.md | 待检 | 新组件前检查组件清单 |
| 数据库变更先查 DATA_MODEL.md | 待检 | 新字段/表前更新数据模型文档 |
| 变更已记录 CHANGELOG.md | 待检 | 所有变更需记录 |
| 无魔法数字 / 魔法字符串 | 待检 | 集中定义常量 |
| 无不必要的 `console.log` | 待检 | 生产代码清理调试日志 |
| 无未使用的导入 / 变量 | 待检 | 保持代码整洁 |

## 2. 代码审查清单

### 结构检查

- [ ] 文件职责单一，不混合 UI / 业务逻辑 / 数据操作
- [ ] 组件文件按 `COMPONENTS.md` 规范命名和放置
- [ ] 新增组件已注册到 `docs/COMPONENTS.md`
- [ ] 共享类型放在 `packages/shared`，不跨包重复定义
- [ ] 自定义 Hook 抽取合理，无过大的 Hook
- [ ] 样式使用 Tailwind CSS，无内联 style 泛滥

### 边界检查

- [ ] 首次打开工作台有 Raindrop 连接引导流程
- [ ] 网络断开时有离线提示和降级处理
- [ ] IndexedDB 操作失败时有错误反馈
- [ ] Raindrop API 超时或限频时有友好提示
- [ ] AI 分类服务不可用时有降级方案（跳过自动分类）
- [ ] 同步冲突时提供冲突视图，用户可选择处理方式

### 依赖检查

- [ ] `packages/shared` 无对 `apps/*` 的反向依赖
- [ ] `packages/db` 只依赖 IndexedDB / Dexie.js
- [ ] `apps/server` 不直接依赖前端代码
- [ ] 无循环依赖
- [ ] 各应用可独立构建和启动

### 接口检查

- [ ] API 响应统一使用 `{ ok, data, error, meta }` 结构
- [ ] 错误码使用 `docs/API.md` 中定义的标准错误码
- [ ] 分页参数和响应格式一致（page / limit / meta.total）
- [ ] 软删除操作返回 `deletedAt` 和 `restoreBefore`
- [ ] `/.well-known/capabilities` 端点无需认证
- [ ] 所有写操作端点需 Bearer Token 认证

## 6. 安全检查

### 输入校验

- [ ] API 入口对 URL 格式进行校验
- [ ] 标签长度和数量有上限限制
- [ ] 备注内容有长度限制
- [ ] 文件夹 ID 格式校验
- [ ] 分页参数范围校验（page ≥ 1，1 ≤ limit ≤ 100）
- [ ] 搜索关键词长度限制，防止超长输入

### 硬编码与密钥

- [ ] Raindrop API Token 不硬编码，走环境变量或安全存储
- [ ] DogEar 的 Bearer Token 不提交到代码仓库
- [ ] AI 服务的 API Key 不硬编码
- [ ] `.env` 文件已加入 `.gitignore`
- [ ] 前端不暴露敏感 Token（仅通过 server 代理）

### API 认证

- [ ] 所有写操作端点（POST / PATCH / DELETE）需要认证
- [ ] `/.well-known/capabilities` 端点无需认证
- [ ] Token 无效时返回 `UNAUTHORIZED`（401）
- [ ] AI 调用删除接口时返回 `FORBIDDEN`（403）
- [ ] 限速机制生效：每分钟 60 次请求上限

### 数据安全

- [ ] 隐私文件夹在导航页默认不展示
- [ ] 隐私内容解锁需密码 / 系统认证
- [ ] 本地数据不上传到第三方服务
- [ ] 操作日志不包含敏感信息（如 Token 明文）
- [ ] 软删除数据在 7 天后自动清理

## 9. 架构健康检查

### DRY（不重复）

- [ ] 书签 CRUD 逻辑集中在 `packages/db`，不在各应用重复实现
- [ ] API 响应格式统一，不各端自定义
- [ ] 标签约定前缀集中定义，不散落各处
- [ ] 错误码和错误消息集中管理
- [ ] 类型定义（Bookmark / SyncQueue / OperationLog）只在 `packages/shared` 定义

### 一致性

- [ ] 三个应用（web / extension / server）使用相同的类型定义
- [ ] 状态字段值一致：`unread` / `reading` / `read` / `organized`
- [ ] 同步状态值一致：`pending` / `syncing` / `synced` / `failed`
- [ ] 错误响应格式一致：`{ ok, error: { code, message } }`
- [ ] 日期字段统一使用时间戳（number）

### 解耦

- [ ] 工作台可独立运行，不依赖服务端在线
- [ ] 导航页可独立运行，不依赖工作台
- [ ] Skill API 服务端可独立部署
- [ ] 同步引擎解耦，可独立启停
- [ ] AI 分类能力解耦，不可用时不影响核心流程

### 项目结构

- [ ] `apps/web` — 工作台（React Web App）
- [ ] `apps/extension` — 导航页（浏览器插件，Manifest V3）
- [ ] `apps/server` — Skill API（Node.js + Hono）
- [ ] `packages/shared` — 共享类型和工具
- [ ] `packages/db` — 数据库层（Dexie.js）
- [ ] `docs/` — 项目文档
- [ ] Turborepo 构建编排正常
