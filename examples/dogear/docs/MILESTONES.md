# DogEar 里程碑计划

- **日期**：2026-08-21
- **版本**：v1.0

---

## 1. Phase 1 概述

**目标**：打通完整流程，实现从 Raindrop.io 同步书签 → 本地管理 → 个人导航页浏览的核心闭环。

Phase 1 覆盖四大模块：

| 模块 | 说明 |
|------|------|
| **Skill API** | 自描述接口，5 个端点，Bearer Token 认证，软删除 + 撤销 |
| **本地数据层** | IndexedDB（Dexie.js）、同步引擎双向同步、冲突处理、操作日志 + 软删除 |
| **工作台 Web App** | 待处理队列 + 整理模式、文件夹树 + 标签导航、网格/列表视图、内联编辑、批量操作、快捷键、导出 |
| **个人导航页浏览器插件** | 新标签页替换、文件夹分组、搜索、待整理提醒、隐私隐藏 |

**预计总工期**：6-8 周

---

## 2. 里程碑拆分

将 Phase 1 拆分为 4 个里程碑，每个里程碑 1-2 周：

### M1：数据基座（第 1-2 周）

> 打通 Raindrop.io 连接，建立本地数据存储，实现基本读写能力。

**核心交付**：
- Dexie.js 数据库初始化，bookmarks / folders / tags 三张核心表
- Raindrop.io OAuth 授权流程 + API 对接（获取 Access Token）
- 基本 CRUD：从 Raindrop 拉取书签到本地 IndexedDB
- 单条书签的本地创建 / 编辑 / 删除

**验收标准**：
- 能通过 Raindrop API 获取用户全部书签并存入 IndexedDB
- 能在本地对书签进行增删改查，数据持久化到 IndexedDB

---

### M2：同步引擎（第 3-4 周）

> 建立本地与 Raindrop 之间的双向同步机制，保证数据一致性。

**核心交付**：
- 同步引擎核心：本地 → Raindrop 推送（Push）
- 同步引擎核心：Raindrop → 本地拉取（Pull）
- 冲突检测与处理策略（Last-Write-Wins + 字段级合并）
- 操作日志（Operation Log）记录每次变更
- 软删除标记 + 删除同步
- 同步状态管理（lastSyncAt、syncStatus）

**验收标准**：
- 本地修改能自动推送到 Raindrop
- Raindrop 端的修改能拉取到本地
- 冲突情况下不丢数据，有明确的处理策略
- 操作日志完整记录每次同步操作

---

### M3：工作台核心（第 5-6 周）

> 构建可用的书签管理工作台界面，支持浏览、搜索、编辑。

**核心交付**：
- 书签列表页面：网格视图 / 列表视图切换
- 文件夹树导航（左侧边栏）
- 标签筛选与导航
- 全局搜索（标题、URL、标签、笔记）
- 内联编辑（点击即编辑标题、标签、笔记）
- 书签详情面板（预览、元信息）
- 基础布局：响应式设计，深色/浅色主题

**验收标准**：
- 能浏览所有书签，按文件夹和标签筛选
- 能搜索并快速定位书签
- 能直接在列表中编辑书签信息

---

### M4：整理与导出（第 7-8 周）

> 实现 Inbox Zero 整理模式、批量操作、导出和快捷键，完成核心闭环。

**核心交付**：
- 整理模式（Inbox Zero）：待处理队列，逐条归档
- 批量操作：多选书签，批量移动 / 打标签 / 删除
- 导出功能：JSON / HTML / CSV / Markdown 四种格式
- 快捷键系统：常用操作键盘快捷键
- Skill API 自描述端点 + 5 个业务端点
- 个人导航页浏览器插件（新标签页替换 + 文件夹分组）

**验收标准**：
- 能通过整理模式高效处理新书签
- 能批量操作书签
- 能导出书签数据
- 浏览器新标签页显示个人导航页

## 5. 风险点

### M1：数据基座

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| Raindrop API 限流（120 次/分钟） | 大量书签首次同步耗时 | 实现分页拉取 + 速率控制，增加本地缓存 |
| OAuth Token 安全存储 | Token 泄露导致数据风险 | 使用浏览器安全存储（chrome.storage.local / localStorage + 加密） |
| IndexedDB 存储配额 | 大量书签超出浏览器存储限制 | 监控存储使用量，提前告警；考虑按需加载 |

### M2：同步引擎

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 冲突数据丢失 | 用户修改被覆盖 | 冲突时保留双方版本，用户手动选择；操作日志支持回溯 |
| 同步中断（网络异常） | 部分数据不同步 | 实现断点续传 + 重试队列；操作日志记录未完成的同步任务 |
| 双向同步死循环 | 本地修改触发推送，推送触发拉取 | 使用 syncDirection 标记避免循环；设置同步冷却时间 |

### M3：工作台核心

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 大量书签渲染性能 | 列表卡顿、滚动不流畅 | 使用虚拟滚动（react-window）；分页加载 |
| 搜索性能 | 实时搜索响应慢 | 客户端全文搜索使用 Fuse.js；大数据量考虑 Web Worker |
| 内联编辑数据一致性 | 编辑中数据被同步覆盖 | 编辑状态锁定，同步时跳过正在编辑的记录 |

### M4：整理与导出

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 浏览器插件 Manifest V3 限制 | Service Worker 生命周期管理复杂 | 使用 chrome.alarms 定时任务；保持状态最小化 |
| 导出格式兼容性 | HTML 导出后无法被其他浏览器导入 | 严格遵循 Netscape Bookmark File Format 规范 |
| Skill API 安全性 | 未授权访问导致数据泄露 | Bearer Token 认证 + 请求频率限制 + 输入校验 |
