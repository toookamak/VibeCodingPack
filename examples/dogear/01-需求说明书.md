# 01. 产品定义

## 01. 产品定义

### 1.1 定位

Bookmark Enhancer 是一个基于 Raindrop.io 的个人书签增强工具。以 Raindrop 为数据底层，通过 **Skill API + 工作台 + 个人导航页** 三部分，构建一套个人书签的收藏、整理、浏览闭环。

### 1.2 核心理念

- Raindrop 是数据存储和稳定性的保障，不替代它，而是在其之上构建更灵活的交互层
- 本地优先，操作即时响应，异步同步到 Raindrop
- AI 能力以 Skill 形式暴露，不绑定任何特定 AI 平台
- 纯个人工具，不考虑多人协作，安全和隐私优先

### 1.3 目标用户

个人用户（本项目为自用设计），有大量书签收藏和整理需求，日常工作涉及多平台信息收集。

# 02. 用户需求与核心工作流

## 02. 用户需求与核心工作流

> 以下为用户在讨论中明确提出的思路和要求，按提出顺序整理。

### 2.1 基础需求

1. 做一个书签工具，数据基于 Raindrop，通过 API 互通
2. 基于 Raindrop 做一个更加便捷的收藏和编辑界面
3. 具有 AI 录入、稍后读清单
4. 快捷编辑分类和其他便捷功能
5. 个人使用，不是团队场景
6. 独立的 Web 界面，移动端不做

### 2.2 痛点描述

1. 现有 Raindrop 收藏形式单一，大多数情况通过浏览器插件收藏
2. 浏览器插件的收藏界面编辑条件有限，只能写文字和标签
3. 收藏后只有文件夹和标签可以归类，管理维度单一
4. Raindrop 主页只有基础的文件夹和书签分类功能，管理界面不够灵活
5. 看中 Raindrop 的数据稳定性且多平台可取，希望以 Raindrop 做数据核心

### 2.3 AI Agent 相关

1. AI 主要是 AI Agent，可以随时随地使用，只要有一个链接发给 Agent 就能完成收藏
2. Agent 自己填写基础必要的内容：根据页面内容属性放在合适的文件夹，打上稍后读标签
3. 用户只需要提供一个链接即可，有什么需要记录的也可以告诉 Agent
4. Skill 不应绑定特定 AI 平台，提供 base URL 和 token 即可，AI 通过链接自描述获取能力
5. 绑定时只需要给 AI 一个链接和 token，AI 自己去发现能做什么，不需要用户反复说明
6. 不排斥 Raindrop 只是数据保存的一种途径，只要数据能安全稳定保存，本地可以做丰富一点

### 2.4 工作台相关

1. 电脑前闲暇之余，在工作台上快速点开稍后读列表，查看哪些内容未整理
2. 需要收纳的收纳，需要阅读的阅读
3. 希望包含拖拽等多种形式，依托 Raindrop 基础功能（如标签）做管理和分类
4. 支持多种形式组织内容：看板、表格、网格等，快速浏览和整理收藏
5. 整理模式可以做，暂时还没想好具体形态，可以按情景分，也可以按功能拆分

### 2.5 数据同步

1. 数据处理完后有序传入 Raindrop 进行保存
2. 定期获取 Raindrop 的数据，以便对通过插件收藏的内容进行同类型整理
3. 双向同步理论上 API 最好，但担心网络问题导致操作不流畅，且官方 API 有调用频率限制
4. 可以考虑部署应用，也可以考虑做成浏览器插件形式，按需求定技术方案
5. 期望操作灵活、数据安全、兼容性好
6. 接受本地优先 + 异步同步的策略
7. Phase 1 需要包含 Raindrop 的数据获取和写入，整个流程要打通，功能后续根据体验慢慢扩展

### 2.6 导出

1. 需要快速导出功能，支持以下格式：
    - 浏览器收藏夹文件（HTML）
    - Markdown 文档
    - CSV 表格
2. 导出用于备份目的

### 2.7 安全与约束

1. 既要限制 AI 非常规情况的能力，也要有兜底机制可还原
2. 要限制 AI 的操作范围，比如不能快速破坏数据（一键改动、一键删除、饱和式填充等极端情况）
3. 个人体验为主，不需要考虑多人分享
4. 要考虑安全性：公网部署需要鉴权，本地部署也需要考虑隐私页面的收藏
5. 软删除机制，保留可恢复周期

### 2.8 导航页

1. 可以延伸做个人主页导航，以浏览器插件或其他形式，依据内容做成个人导航页
2. 导航页看资源情况设计，可以放在后续阶段

# 04. 核心功能设计

## 4.1 Skill API

### 4.1.1 自描述机制

AI 平台绑定时只需提供：

- 服务地址（Base URL）
- 访问令牌（Token）

AI 通过访问 `/.well-known/capabilities` 端点自动获取可用能力列表、参数说明和使用示例。

### 4.1.2 Skill 清单

|---|---|---|---|
|Skill|描述|输入|说明|
|`save_bookmark`|收藏一个链接|url（必填）、note（可选）|自动抓取元数据、AI 分类、生成标签、标记稍后读|
|`search_bookmarks`|搜索书签|query、filters（可选）|支持自然语言和条件筛选|
|`update_bookmark`|修改单条书签|id、修改字段|文件夹/标签/备注/状态|
|`list_bookmarks`|列出书签|状态、文件夹、标签、limit|支持筛选和分页|
|`get_stats`|获取统计信息|无|收藏总数、各分类数量等|

### 4.1.3 AI 记忆（偏好学习）

- 每次 AI 执行保存操作后，记录分类和标签的选择模式
- 累积形成用户偏好模型，提升后续自动分类的准确度
- 偏好数据存在服务端，Skill 被调用时自动参考

## 4.2 工作台

### 4.2.1 整体布局

- 左侧：导航栏（待处理、收藏、最近、文件夹树、标签云、统计、导出、日志）
- 顶部：快速搜索（⌘K）、同步状态、设置入口
- 中部：主内容区，支持视图切换
- 底部：状态栏 / 批量操作栏

### 4.2.2 视图模式

|---|---|---|
|视图|描述|适用场景|
|网格视图|卡片式，展示封面图 + 标题 + 标签|快速浏览、凭直觉分类|
|列表视图|紧凑行，一屏展示更多条目|批量扫描、批量操作|
|看板视图|按状态分列（未读/在读/已整理）|追踪阅读进度、管理稍后读|

### 4.2.3 整理模式（Inbox Zero）

- 沉浸式界面，只显示待处理队列
- 每张卡片展示：标题、URL、AI 摘要、AI 建议的分类和标签
- 三个核心动作：采纳建议 / 修改 / 丢弃
- 支持全键盘操作（Enter 采纳、E 修改、D 丢弃、←→ 切换）
- 进度条显示处理进度

### 4.2.4 内联编辑

悬浮卡片时浮现操作区：

- 点击文件夹 → 下拉选择器，可移动
- 点击标签 → 标签选择器，可增删
- 点击状态 → 循环切换
- 快捷操作：移动、打标签、标记已读、更多菜单

### 4.2.5 批量操作

多选后出现批量工具栏：

- 移动到文件夹
- 添加标签
- AI 批量整理（分析后给出统一分类方案）
- 标记已读
- 删除（需确认）

### 4.2.6 快捷键

|---|---|---|
|范围|按键|功能|
|全局|⌘K|快速搜索/命令面板|
|全局|N|快速收藏（弹出输入框）|
|整理模式|Enter|采纳 AI 建议|
|整理模式|E|打开编辑|
|整理模式|D|标记丢弃|
|整理模式|S|跳过|
|整理模式|← →|切换上/下一条|
|通用|Esc|关闭弹窗/退出当前模式|
|通用|Space|列表中预览|

## 4.3 本地数据层

### 4.3.1 数据结构

核心表：

- `bookmarks`：书签主数据（含同步状态字段）
- `sync_queue`：待同步变更队列
- `operation_log`：操作日志（含撤销数据）

### 4.3.2 同步引擎

**写入流（本地 → Raindrop）**：

```
用户操作/AI操作 → 写入 IndexedDB（即时）→ 写入 sync_queue → 同步引擎后台轮询（每 30s）→ 按 API 限速逐条推送
```

**读取流（Raindrop → 本地）**：

```
定时拉取（每 5 分钟或手动刷新）→ 对比 lastSyncAt 拉取增量 → 对比本地版本处理冲突 → 写入 IndexedDB
```

**冲突处理**：

- 默认以本地为准
- 提供冲突视图，用户可选择"用本地的"、"用 Raindrop 的"或"手动合并"

## 4.5 个人导航页

### 4.5.1 形态

浏览器插件，替换浏览器新标签页。

### 4.5.2 功能

- 按文件夹分组展示常用链接
- 显示近期在读内容
- 搜索框（搜索书签或输入网址）
- 待整理提醒入口
- 隐私文件夹默认隐藏

### 4.5.3 数据来源

- 优先从本地数据层获取（IndexedDB）
- 降级方案：直接调 Raindrop API（只读）

### 4.5.4 隐私控制

- 设置中可标记私密文件夹/标签
- 导航页默认不展示私密内容
- 查看私密内容需解锁（密码/系统认证）

9.1 整体风格

导航页以图标 + 图标文件夹的形式呈现书签内容，视觉上接近 iOS/Android 启动器的体验：
  - 每个书签以图标 + 名称的形式展示，不显示 URL、摘要等冗余信息
  - 同一文件夹下的书签归入一个"图标文件夹"，文件夹本身也以图标形式呈现
  - 点击文件夹图标展开，显示内部书签
  - 整体为网格布局，行列规整，视觉干净

核心原则：简洁、快速定位、像桌面启动器一样直觉化操作。

    - 每个文件夹图标占 1 格
    - 后续小组件可占 2格、4格 等不同尺寸

9.3 图标文件夹

  外观：
    - 文件夹以一个聚合图标呈现（类似 iOS 文件夹，内部显示 4 个小图标预览）
    - 文件夹下方显示名称
    - 点击文件夹 → 展开为浮层或内嵌展开，显示该文件夹下所有书签图标

  展开行为：
    - 点击文件夹图标，以浮层 overlay 形式在当前位置展开
    - 展开后显示文件夹内所有书签的图标网格
    - 点击浮层外部区域关闭
    - 书签数量多时，浮层内支持滚动

  文件夹图标来源：
    - 自动取文件夹内前 4 个书签的 favicon 拼合
    - 也支持用户手动指定文件夹图标


9.4 书签图标

  构成：
    - 网站 favicon 作为图标主体
    - favicon 不可用时，降级为首字母图标（首字符 + 随机柔和背景色）
    - 图标下方显示书签名称（单行，超出截断）

  数据来源：
    - favicon：收藏时自动获取并缓存
    - 名称：取 Raindrop 中的 title，可由用户在导航页直接重命名（仅影响导航页显示，不改 Raindrop 原始数据）


9.5 分页

  当书签数量超出单页网格容量时，支持分页：

  表现形式：
    - 页面底部显示页码指示点（类似手机桌面的多页指示）
    - 左右滑动或键盘 ← → 切换页面
    - 页码指示器：● ○ ○（表示当前在第1页，共3页）

  每页内容：
    - 每页是独立的网格空间
    - 默认第一页放常用/高频书签和文件夹
    - 用户可拖拽图标在页间移动，自定义每页内容
    - 新收藏的内容默认放在最后一页的末尾，或放入一个"新收藏"临时区域

  页数：
    - 不限制最大页数
    - 但建议默认不自动生成过多空页


9.6 未来扩展：小组件

后续考虑在网格中插入小组件，与书签图标混排。组件也占用网格格子，但可占多格。

  可能的小组件：

    稍后读清单（占 2x2 或 2x3 格）
      - 显示最近 5-8 条未读收藏
      - 每行：标题 + 来源域名
      - 点击条目直接打开原文
      - 底部"查看全部"链接到工作台的待处理视图
    
    待办/任务（占 2x2 格）
      - 简单的 checklist
      - 数据来源待定（本地存储或对接外部服务）
      - 支持快速添加、勾选完成
    
    最近访问（占 2x1 或 2x2 格）
      - 显示最近打开过的书签
      - 快速回到之前浏览的内容
    
    时钟/日期（占 2x1 格）
      - 当前时间和日期
      - 极简显示

  小组件的网格规则：
    - 最小单位：1x1（与普通图标同格）
    - 常见尺寸：2x1、2x2、3x2、4x2
    - 小组件不能与图标重叠，必须占据完整的格子
    - 小组件支持拖拽改变位置
    - 初期可固定几个预设尺寸，不做自由缩放，降低实现复杂度


9.7 交互行为

  点击书签图标：在当前标签页打开该链接
  点击文件夹图标：展开浮层，显示文件夹内容
  长按/右键图标：弹出菜单（编辑、移动、删除、修改图标）
  拖拽图标：可重新排列位置，可跨页拖拽
  页面空白区域双击：进入编辑模式（可移动/删除/添加图标）


9.8 搜索

  页面顶部居中放置搜索框：
    - 搜索范围：所有书签（包括未在当前页显示的）
    - 搜索结果以下拉列表形式呈现
    - 结果中可直接点击打开
    - 支持模糊匹配标题和域名


9.9 隐私

  按照 4.5.4 节的隐私控制策略：
    - 标记为私密的文件夹/标签在导航页不显示
    - 默认展示安全内容
    - 查看私密内容需手动解锁

10.1 概述

导航页底部（可配置）增加一个常驻的 Docker 栏，类似 macOS Dock 或 iOS 底部 Dock，
用于放置用户最常用的或手动收藏的图标，始终可见，不随分页切换而消失。

Docker 为可开关功能，默认开启，可在设置中关闭。


10.2 位置与形态

  默认位置：页面底部居中
  可选位置：顶部居中 / 左侧垂直 / 右侧垂直（设置中配置）

  形态：
    - 半透明磨砂背景条，悬浮在页面内容之上
    - 与主网格区域分离，不占用网格格子
    - 内部图标排列规则与主网格一致（等间距水平排列）
    - 图标数量建议上限：12 个（超出时图标自动缩小适配，或出现溢出提示）

  底部 Docker 示意：

    ┌─────────────────────────────────────────────────┐
    │                                                 │
    │              （主网格区域，随分页切换）            │
    │                                                 │
    │                                                 │
    ├─────────────────────────────────────────────────┤
    │              ● ○ ○  （分页指示器）               │
    ├─────────────────────────────────────────────────┤
    │   ┌─────────────────────────────────────────┐   │
    │   │ 🔗  🔗  📁  🔗  🔗  🔗  🔗  🔗         │   │
    │   │Figma MDN 设计 GitHub ...                │   │
    │   └─────────────────────────────────────────┘   │
    └─────────────────────────────────────────────────┘
               ↑ 半透明磨砂底栏，始终固定显示


10.3 Docker 内容

  放入 Docker 的项目类型：
    - 单个书签图标（常用网站）
    - 图标文件夹（常用文件夹整体放入）
    - 后续可放小组件（如待办、时钟等小尺寸组件）

  添加方式：
    - 从主网格区域拖拽图标到 Docker 栏 → 自动添加
    - 右键/长按图标 → 菜单中选"添加到 Docker"
    - 设置页面中手动管理 Docker 内容列表

  移除方式：
    - 从 Docker 栏拖拽图标到主网格区域或页面外 → 移除
    - 右键/长按 Docker 中的图标 → 菜单中选"从 Docker 移除"
    - 设置页面中管理

  排序：
    - Docker 内图标支持拖拽排序
    - 排序结果持久化保存


10.4 交互行为

  点击：与主网格中的图标行为一致（书签打开链接，文件夹展开浮层）
  拖拽：拖入添加，拖出移除，内部拖拽排序
  右键/长按：弹出菜单（打开、移除、在主网格中定位）
  悬浮：图标轻微放大 + 名称 tooltip 提示（因为 Docker 空间紧凑可能不显示名称）


10.5 开关与配置

  在设置页面中提供以下选项：

    启用 Docker：[开 / 关]（默认：开）
    
    位置：[底部 / 顶部 / 左侧 / 右侧]（默认：底部）
    
    显示名称：[开 / 关]（默认：关，仅显示图标，节省空间）
    
    最大图标数：[1-16]（默认：12）
    
    图标大小：[小 / 中 / 大]（默认：中）


10.6 数据存储

  Docker 内容列表存储在本地（IndexedDB 或 localStorage），结构：

    docker_items: [
      { type: "bookmark", id: "rd_123456", order: 1 },
      { type: "folder", id: "col_789", order: 2 },
      { type: "bookmark", id: "rd_234567", order: 3 },
      ...
    ]

  Docker 的数据完全属于导航页本地配置，不写入 Raindrop，不参与同步。
  清除浏览器数据时需注意备份此配置。


10.7 与主网格的关系

    - Docker 是独立于主网格的常驻区域，不占网格格子
    - 主网格中仍然可以显示与 Docker 中相同的书签（Docker 相当于快捷方式/收藏夹）
    - 删除主网格中的书签时，Docker 中对应的快捷方式也同步移除
    - Docker 中移除图标不影响主网格中的原始书签

# 05. 安全与权限

## 5.1 安全策略

### 5.1.1 AI 操作边界

|---|---|
|类别|策略|
|禁止执行|删除书签、修改文件夹结构、批量操作（默认）|
|允许执行|收藏新链接、搜索列出、单条修改、获取统计|
|限速|每分钟最多 60 次请求，连续写入超 10 次/分钟触发警告|

### 5.1.2 兜底机制

- **软删除**：标记删除后本地保留 7 天，可一键恢复
- **操作日志**：所有写操作记录，支持查看和回滚
- **撤销条**：工作台界面底部常驻撤销提示
- **冲突处理**：本地与 Raindrop 数据冲突时，以本地为准，提供手动合并选项

------



**设想 1：导航页与工作台的关联**



书签导航页中的书签可以在工作台中标记"是否在导航页展示"。至于导航页中如何展示（图标样式、排列位置、所属区域等），由导航页侧的编辑来决定。导航页和工作台之间的关联可以做强关联也可以做弱关联——强关联意味着工作台中的标记直接控制导航页的展示，弱关联意味着两边独立管理，只是数据同源。当然这个关联功能也是可用可不用的，不是必须项。



------



**设想 2：产品形态的多种可能**



当前阶段的目标是本地部署、个人自用。但不排除将来提供云端版本和账号体系，进行产品商业化。也就是说产品架构需要考虑将来从本地部署扩展到云端多用户的可能，数据层和接口层的设计要为此留有余地，但当前不需要实现云端相关功能。



------



**设想 3：数据存储策略**



数据怎么存需要提前考虑好，需要分两个层面来想：

- 使用存储：日常操作中读写的数据，需要即时响应、结构清晰
- 备份存储：用于备份和恢复的数据，可以根据备份的形式和程度舍弃掉一些非必要信息（比如操作日志、同步状态、临时缓存等），不一定需要和使用存储完全一致



------



**设想 4：未来延伸——MD 形式的剪藏**



将来可能会延伸出 Markdown 形式的剪藏功能。剪藏的内容基本只有图片和文字，不会有其他重的附件（如视频、PDF、压缩包等）。也就是说剪藏是轻量级的，聚焦于图文内容的保存。



------



**设想 5：产品化收费**



如果将来做产品化，会根据功能和使用程度来收费。具体收费模式和价格体系待定，但基本方向是功能分级收费（免费基础功能 + 付费高级功能）和/或按使用量收费。



------



**设想 6：核心设计原则**



每个功能点尽量围绕一个情景来设计。大的功能围绕一个流程来设计。这是基本核心思路。 在此基础上，额外可提供更多便利功能来丰富体验。 需要注意的是，此条并非绝对原则。核心原则更准确的表述是：**功能要丰富，流程要清晰，使用要简单**。情景驱动是设计方法，不是硬性约束。



------



**设想 7：导航页小工具的开放策略**



导航页的小组件/小工具不会无限制地全部开放。优先提供核心功能的小组件，初步确定的核心小组件范围包括：

- 待办
- 稍后读
- 便签
- 书架（展示常用或精选书签的特殊组件）
- 资讯（可能对接外部信息源）



后续根据使用情况再考虑开放更多小工具。



------



**设想 8：看板的多维度切换**



看板视图并非只能以状态（未读/在读/已整理）来分类分列。后续可能考虑支持多种维度的切换，例如按文件夹分列、按标签分列、按优先级分列、按时间维度分列、按情景/用途分列等。用户可以根据当前的整理需要选择不同的维度来查看和操作。



------



**设想 9：AI 记忆沉淀**



AI 可以根据用户的使用习惯沉淀记忆。不仅是收藏时的分类偏好学习（这个在需求文档中已有），而是更广泛的使用行为记忆——包括用户的阅读习惯、标签使用偏好、文件夹组织逻辑、常用的搜索模式、整理时的决策倾向等。沉淀的记忆用于让 AI 在后续交互中提供更精准的建议和服务。
